# English Reader 产品需求与设计分析（文字版草案）

## 1. 文档目的

本文件将当前的 English Reader 从“可阅读、可查词的原型”推进为“可持续使用的英文阅读学习工具”的需求、范围和设计决策写清楚。它可作为新 Codex 任务的唯一上下文来源；实现前仍应先拆出独立的实施计划。

**产品定位**：面向中国高中生、大学生与考研用户的本地优先英文阅读学习工具。用户通过真实英文文章阅读、词汇标记、收藏与复习，持续积累词汇和阅读记录。

**核心原则**：

- 阅读优先：任何学习功能都不能打断正文阅读。
- 本地优先：第一阶段无账号、无后端，用户数据默认只保存在浏览器。
- 可迁移：所有用户数据都能导出和恢复；未来云同步只替换存储实现，不重写页面逻辑。
- 渐进交付：稳定性、学习闭环、云同步与智能能力分阶段上线。

## 2. 当前产品基线

### 已有能力

- 文章首页：按难度、来源筛选；支持默认、字数、随机排序及网格/列表视图。
- 阅读页：Markdown 文章、词汇难度高亮、悬浮释义、词汇面板、文章收藏、阅读标记。
- 精读：点击段落后可在侧栏看到预置的中英对照句子。
- 词汇：可将词标记为“生词收藏”或“熟词”；两种状态互斥。
- 收藏：收藏文章、生词、熟词均保存在浏览器 `localStorage`。
- 移动端：底部导航与响应式文章卡片已经存在。

### 当前缺口与技术债

- “导入文章”和“学习统计”仅是占位页。
- ESLint 有 8 个错误、6 个警告；TypeScript 类型检查已通过。
- 无系统化的 loading、error、empty 状态；错误会直接影响页面体验。
- 现有 `localStorage` 已有抽象函数，但没有统一 Repository 接口、数据版本或备份机制。
- 首页来源筛选在窄屏是横向滚动，需明确为可访问、可提示的交互。
- 无自动化测试基线。

## 3. 已确认的产品决策

1. **路线范围**：采用完整产品迭代路线图，而不是只处理稳定性或单一功能。
2. **数据策略**：分两阶段。第一阶段本地优先，并提供备份导出/导入；第二阶段再增加账号与跨设备同步。
3. **文章导入**：第一阶段支持粘贴英文正文和导入 Markdown 文件；URL 抓取列入后续阶段。
4. **统计范围**：第一阶段提供基础概览、近 7/30 天趋势与每日学习热力图；复习正确率、连续学习、目标提醒后置。
5. **交付约束**：本文档只用于本地改进与后续新任务执行；未经用户确认不得提交或推送到 GitHub。

## 4. 用户与成功标准

### 目标用户

| 用户 | 主要任务 | 关键痛点 |
| --- | --- | --- |
| 高中/大学英语学习者 | 利用文章积累词汇、反复阅读 | 查词打断阅读、词汇难沉淀 |
| 四六级/考研备考者 | 按难度选择文章、识别薄弱词 | 词汇清单与阅读行为脱节 |
| 自主学习者 | 导入自己找到的文章 | 内容无法统一管理、数据易丢失 |

### 成功标准

- 用户能在 3 步内从首页进入阅读、收藏陌生词，并在生词页找到该词。
- 用户能导入一篇英文文本或 Markdown，预览后立即进入同样的阅读与查词体验。
- 用户能看懂过去 7/30 天的阅读变化和总体学习积累。
- 用户可下载完整数据备份，并在同一浏览器恢复；非法备份不能破坏现有数据。
- 关键页面在手机宽度与桌面宽度均无横向页面溢出，核心操作可通过键盘完成。

## 5. 分阶段范围

### 阶段 0：质量与体验基线

**目标**：在新增功能前，消除已知质量门槛并建立可验证的基础。

- 修复全部 ESLint 错误；警告逐项评估并消除或记录原因。
- 统一客户端初始化方式，避免在 effect 中同步 setState 的规则冲突。
- 修复 `ArticleBody` 渲染期读取 ref 的问题。
- 加入根级 `loading`、`error`、`not-found` 和关键列表空状态。
- 优化移动端筛选栏、阅读页侧栏的窄屏行为及触控可用性。
- 为词汇解析、导入解析、存储迁移和统计计算建立自动化测试。

**不包含**：新学习功能、账号系统、云数据库。

### 阶段 1：本地学习闭环

**目标**：让用户能导入内容、完成阅读与词汇沉淀、看到学习成果并安全备份。

1. **导入文章**：粘贴文本和 Markdown 文件，支持预览、校验、重复提示与保存。
2. **统一数据层**：引入 Repository 接口、版本化本地数据和迁移机制。
3. **数据管理**：提供 JSON 备份导出、预检、合并恢复和失败保护。
4. **学习统计**：总览卡、7/30 天趋势、学习热力图、词汇和阅读数据。
5. **词汇复习基础**：在生词页提供待复习视图、已复习标记和最近复习日期；不引入复杂算法。

### 阶段 2：账户与跨设备

**目标**：在不改变阶段 1 页面行为的前提下，增加登录、云端持久化与冲突处理。

- 邮箱或第三方登录。
- 云端同步文章、词汇、阅读和设置。
- 离线优先队列、最后写入时间和冲突提示。
- 首次登录时导入当前本地数据。

### 阶段 3：增强学习能力

- 受控的 URL 导入：服务端抓取、来源白名单、版权说明、内容清洗和失败降级。
- 间隔复习、正确率、连续学习、目标和提醒。
- 句子收藏、句法分析和可选的 AI 辅助解释。
- 更多内置文章、全文搜索、主题筛选与内容推荐。

## 6. 信息架构

| 页面/入口 | 阶段 1 职责 | 主要操作 |
| --- | --- | --- |
| 发现文章 | 找到合适文章并进入阅读 | 难度/来源筛选、排序、收藏、进入文章 |
| 阅读页 | 完成沉浸式阅读与词汇操作 | 高亮查词、收藏/标熟、精读、标记已读 |
| 导入文章 | 将私有内容进入学习流 | 粘贴、上传 Markdown、预览、保存 |
| 生词复习 | 管理待学词 | 筛选、查看释义、标复习、标熟/移除 |
| 熟词 | 回顾已掌握词 | 筛选、撤销熟词标记 |
| 文章收藏 | 回看文章 | 筛选、排序、进入阅读 |
| 学习统计 | 反馈学习积累 | 总览、趋势、热力图、数据说明 |
| 数据与设置 | 保护与迁移数据 | 导出、校验导入、恢复结果、隐私说明 |

移动端底部导航保留高频入口：阅读、生词、熟词、统计与“更多”。“更多”内应显式提供导入文章、文章收藏、数据与设置；避免为每个次级功能挤占底部导航。

## 7. 核心功能需求

### 7.1 导入文章

#### 支持的输入

- 直接粘贴英文正文，必填；标题可选。
- 上传 `.md` 文件，UTF-8 编码；可读取 frontmatter 的 `title`、`source`、`difficulty`、`topic`，缺失时由用户补充或使用默认值。
- URL 输入框在阶段 1 不显示为可用功能；可保留“后续支持 URL 导入”的说明。

#### 流程

1. 用户选择“粘贴文本”或“上传 Markdown”。
2. 系统解析内容，去除空白，计算英文词数并校验长度。
3. 用户在预览页确认标题、来源、难度、主题与正文摘要。
4. 系统基于规范化正文计算内容指纹；发现相同内容时提示“打开已有文章”或“仍保存副本”。默认不自动覆盖。
5. 用户确认保存后，创建 `ImportedArticle` 并跳转到阅读页。

#### 校验与错误

- 正文为空或英文词数低于 20：禁止保存并给出原因。
- 文件格式、编码或 frontmatter 无法解析：提示可改用粘贴文本，不丢失已读取的纯文本。
- 单篇正文超过设定上限（建议 100,000 字符）：拒绝写入并说明本地性能限制。
- 本地存储写入失败：不改变当前数据，保留表单内容，提示用户导出旧数据或释放浏览器空间。

### 7.2 词汇与复习

- 单词状态在同一用户数据集内互斥：`saved`（待学/收藏）与 `known`（已掌握）不能同时存在。
- 收藏时记录词汇释义、词性、难度、来源文章、创建时间、最近复习时间和复习次数。
- 阶段 1 的“复习”只要求用户主动标记“本次已复习”；不宣称记忆科学算法。
- 生词页增加三个视图：全部收藏、待复习、最近复习；支持难度筛选和搜索。
- 已标熟的词不参与正文陌生词高亮；撤销熟词后应立即恢复高亮资格。

### 7.3 学习统计

#### 指标定义

- **已读文章数**：至少打开过一次的不同文章数；导入文章同样统计。
- **累计阅读词数**：已读文章的英文词数去重后求和；同一篇文章重复阅读不重复累加。
- **学习天数**：存在至少一个阅读、收藏、标熟、复习或导入事件的自然日数。
- **生词收藏数/熟词数**：当前状态数量，不是历史累计。
- **近 7/30 天活动量**：每日活动事件数与阅读词数；按本地时区归属自然日。
- **热力图**：最近 365 天中每个自然日的活动强度，按事件数分档；0 为无活动。

#### 页面内容

- 顶部四张概览卡：已读文章、累计词数、学习天数、当前生词数。
- 时间范围切换：7 天与 30 天；曲线或柱状图显示阅读词数与活动量。
- 365 天热力图，悬浮或聚焦时显示日期、事件数和阅读词数。
- 首次使用无数据时显示解释性空状态和“开始阅读/导入文章”入口。

### 7.4 备份与恢复

- 导出生成一个 JSON 文件，包含 `schemaVersion`、导出时间、应用版本和全部用户域数据。
- 导入先在内存中解析、验证并展示摘要：文章数、收藏词数、熟词数、活动记录数和来源版本。
- 恢复模式提供“合并”和“替换”：默认合并；替换必须二次确认。
- 合并规则：以稳定 id/规范化单词为键；较新的更新时间优先，活动记录按事件 id 去重。
- 任意校验失败时不写入存储；成功后报告新增、更新、跳过和失败数量。

## 8. 数据与架构设计

### 8.1 Repository 边界

页面、Context 和统计计算不得直接读取 `localStorage`。它们依赖面向业务的 Repository：

- `ArticleRepository`：内置文章查询、导入文章 CRUD、内容去重。
- `WordRepository`：生词、熟词、复习记录和状态转换。
- `ProgressRepository`：阅读活动与统计查询。
- `SettingsRepository`：高亮、精读、筛选偏好和数据版本。
- `BackupRepository`：导出、预检、合并与替换恢复。

阶段 1 由 `Local*Repository` 实现；阶段 2 增加 `Remote*Repository` 或同步适配器。页面 API 保持不变。

### 8.2 核心实体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `ImportedArticle` | id、contentHash、title、source、content、difficulty、topic、createdAt、updatedAt | 用户导入的文章，与仓库 Markdown 文章区分 |
| `WordProgress` | word、status、definition、pos、difficulty、articleIds、createdAt、lastReviewedAt、reviewCount、updatedAt | 一词一条权威状态记录 |
| `ReadingActivity` | id、articleId、date、type、wordCount | `type` 为 opened/read/saved-word/known-word/reviewed/imported 等 |
| `UserSettings` | highlightEnabled、closeReadingEnabled、gallery filters、schemaVersion | 仅保存用户偏好与版本 |
| `BackupEnvelope` | schemaVersion、exportedAt、payload | 导入导出的唯一格式 |

所有时间使用 ISO 8601 完整时间；展示与日统计时再转换为本地日期。所有可迁移数据都要有稳定 id 与 `updatedAt`。

### 8.3 状态和事件

- 阅读一篇文章：若首次打开，写入 `opened` 活动；显式完成或离开前达到阅读阈值后写入 `read` 活动。阶段 1 可先沿用“打开即已读”，但接口必须能支持后续更准确规则。
- 收藏词、标熟词、撤销词状态、导入文章与复习均写入活动事件。
- 统计从活动日志和当前实体计算，不在多个组件间维护容易失真的计数器。

## 9. 非功能要求

### 体验与可访问性

- 主要文字与背景达到 WCAG AA 对比度；难度不能只依赖颜色，应保留文字标签和点位说明。
- 所有按钮有可读的 `aria-label`；筛选按钮暴露选中状态。
- 弹窗与悬浮词义在触屏设备提供点击触发与关闭方式，不能只依赖 hover。
- 320px 宽度不出现整个页面横向滚动；筛选条局部横滚时需有视觉提示。
- 空、加载和失败状态有明确下一步操作，不能只显示技术错误。

### 性能与隐私

- 词汇表仅加载一次并缓存；大文章的高亮与解析需避免阻塞主线程。
- 导入文本不上传到服务端；导出文件仅由用户手动下载。
- 不采集用户文章、词汇或学习数据；若阶段 2 添加分析，必须单独征得同意。

### 质量门槛

- `npm run typecheck`、`npm run lint`、`npm run build` 均须通过。
- 为 Repository、导入解析、数据迁移、备份合并和统计计算添加自动化测试。
- 关键用户流程至少进行一次桌面与手机宽度浏览器验证。

## 10. 验收标准

### 阶段 0

- ESLint 为 0 error；所有保留 warning 有明确理由或被修复。
- 首页、阅读页、收藏页、导入页、统计页都有 loading/error/empty 状态。
- 在 320px、768px、1280px 三种宽度下完成首页筛选与阅读页操作，无不可达控件。

### 阶段 1

- 粘贴英文文本与 Markdown 文件均可完成“输入 → 预览 → 保存 → 阅读”。
- 导入的文章可被收藏、标记已读、查词、收藏词和标熟，行为与内置文章一致。
- 重复文章、空内容、损坏文件、超长文件和存储失败均有可理解提示，且不丢数据。
- 统计页指标与已保存活动记录一致；7/30 天范围和热力图日期正确。
- 导出后在同一浏览器执行合并恢复，数据不重复；非法备份不会改变原数据。

### 阶段 2

- 登录前后本地数据可迁移；不同设备的同一数据可同步。
- 离线操作恢复网络后可同步；冲突有明确且可复核的处理结果。

## 11. 明确不做的内容

- 阶段 1 不做 URL 抓取、账号注册、后端数据库、支付、社交功能或自动 AI 解析。
- 阶段 1 不把“打开文章”包装为精确的阅读理解成绩，不产生未经验证的学习结论。
- 阶段 1 不删除现有内置 Markdown 内容体系；导入文章是并行内容来源。

## 12. 推荐实施顺序

1. 阶段 0 质量门槛与测试基线。
2. 统一 Repository、数据版本和活动模型。
3. 粘贴/Markdown 导入及阅读路由整合。
4. 备份导出、预检与恢复。
5. 统计计算与统计页面。
6. 生词复习基础与移动端细节。
7. 阶段 1 全流程回归、无障碍和性能验证。
8. 评估阶段 2 的认证与云存储方案，另立规格后实施。
